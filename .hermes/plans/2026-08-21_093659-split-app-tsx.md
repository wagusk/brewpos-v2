# Split App.tsx into modules

> **For Hermes:** Execute task-by-task. Each task = 1 file move + 1 verification + 1 commit.

**Goal:** Split the 2,652-line `frontend/src/App.tsx` into per-screen modules + shared helpers, adopting the existing `components/` stubs. No behaviour change. Same design, same CSS, same UX.

**Architecture:** One screen = one file under `frontend/src/screens/`. Shared helpers under `frontend/src/common/`. Entry point `App.tsx` becomes a thin router that picks a screen and provides the toast hook. The `App` shell (Root + Sidebar + topbar) stays in `App.tsx` because it owns the global screen state.

**Tech Stack:** React 18, TypeScript, Vite, lucide-react. No new dependencies.

**Key constraint:** No CSS changes. No design changes. Existing classes preserved verbatim. `styles.css` keeps every selector.

**Why `components/` and not more granular files:** POSCard/POSChip/etc. are real DOM primitives used in many places. They belong in `components/`. Per-screen files contain *the screen's composition*, not primitives.

---

## Strategy

1. **Bottom-up**: move helpers first (no dependencies). Then primitives. Then screens. Then `App.tsx` shrinks last.
2. **One file per task**: each move is a single commit. Easy to review, easy to revert.
3. **Verify after every task**: `npx tsc --noEmit` must stay clean. `npm run build` must succeed at the end.
4. **No design changes**: every className stays. Every CSS rule stays. Every layout stays.

```ts
export const money = (value: number) =>
  new Intl.NumberFormat(undefined, {
    style: 'currency',
    currency: 'USD',
    minimumFractionDigits: 2,
  }).format(value);

export const title = (value: string) =>
  value.replace(/[._-]/g, ' ').replace(/\b\w/g, (c) => c.toUpperCase());
```

2. Create `common/auth.ts`:
```ts
import type { User } from '../types'

export const ROLE_PERMISSIONS: Record<string, string[]> = {
  admin: [], master: [], superuser: [],
  cashier: ['dashboard.view','menu.view','pos.view','order.open','order.close','order.cancel','order.append'],
  waiter: ['dashboard.view','menu.view','pos.view','order.open','order.append'],
  kitchen: ['dashboard.view','kitchen.view','bar.view','menu.view','kitchen.serve','bar.serve'],
  bar: ['dashboard.view','kitchen.view','bar.view','menu.view','kitchen.serve','bar.serve'],
}

export const can = (user: User, permission: string) => {
  if (!user) return false
  if (user.role === 'admin' || user.role === 'master' || user.role === 'superuser') return true
  if ((user.permissions ?? []).includes(permission)) return true
  return (ROLE_PERMISSIONS[user.role] ?? []).includes(permission)
}
```

3. Create `common/useToast.ts`:
```ts
import { useState } from 'react'

export type Toast = { message: string; kind: 'success' | 'error' | 'info' }
export type NotifyFn = (message: string, kind?: Toast['kind']) => void

export function useToast() {
  const [toast, setToast] = useState<Toast | null>(null)
  const notify: NotifyFn = (message, kind = 'success') => {
    setToast({ message, kind })
    window.setTimeout(() => setToast(null), 3500)
  }
  return { toast, notify }
}
```

4. Create `common/index.ts`:
```ts
export * from './format'
export * from './auth'
export * from './useToast'
```

5. Modify `App.tsx`: replace inline `money`, `title`, `can`, `ROLE_PERMISSIONS`, `useToast`, `Toast` with `import { ... } from './common'`. The values must be removed from App.tsx, not duplicated.

Expected: clean.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Circular imports between screens and App.tsx | App.tsx imports screens, never the reverse |
| `Metric`/`PanelTitle` moved twice (chrome then Dashboard) | Only export once from `common/chrome.tsx`; Dashboard imports from there |
| CSS class collisions after component adoption | Don't migrate components in Task 12 unless CSS already exists |
| Lost imports during move | tsc --noEmit after every task catches this immediately |
| App.tsx gets stuck with duplicate exports | After Task 2, remove all moved symbols from App.tsx |

## What I will NOT do

- Change CSS
- Change visual design
- Add new dependencies
- Migrate to Redux / Zustand (the current `useState` model works)
- Rewrite state management
- Adopt the POS* components if no current usage needs them (defer to Task 12)
